# Backend overview

FastAPI app managed with uv (`pyproject.toml`, `uv.lock`). Serves the static Next.js export from `static/` at `/` (a build output, gitignored; the Dockerfile copies it in) and the JSON API under `/api`.

## Files

- `main.py`: creates the app, runs `db.init_db()` on startup, includes the auth and boards routers, serves `GET /api/hello`, mounts `static/`.
- `db.py`: SQLite via stdlib `sqlite3`. `connect()` (one connection per call, foreign keys on, commits or rolls back). `init_db()` creates the folder and file, sets WAL mode, applies pending `MIGRATIONS` (script n moves `PRAGMA user_version` from n to n + 1, each in one transaction; append only, never edit a script that has run on real data), and creates the demo user `user` / `password`. Password hashing (scrypt, random salt, `scrypt$salt$hash`), users, sessions (sha256 of the token, 7 days, expired rows deleted on check). `create_user` also creates "My first board" with the 5 default columns and the 8 demo cards (`_create_board`). Boards: `list_boards`, `create_board` (5 default columns, no cards), `rename_board`, `delete_board`, `get_board` (API shape), `save_board` (whole-board replace in one transaction: deletes the board's cards and unlisted columns, upserts columns in order, inserts cards); all scoped to a user id, so another user's board behaves as missing. Schema: `docs/schema.json`, `docs/DATABASE.md`.
- `boards.py`: `GET`/`POST /api/boards` (list `{id, name}` in order, create), `PATCH`/`DELETE /api/boards/{id}` (rename, delete; the last board can be deleted), `GET`/`PUT /api/boards/{id}` (whole board `{columns: [{id, title, cardIds}], cards: {id: card}}`). Pydantic validates names (1 to 60 characters, trimmed), titles, at least one column, unique column ids, every card listed exactly once, card keys matching ids, and card fields (`dueDate` ISO date, `priority` low/medium/high, up to 8 `labels` of 1 to 24 characters, trimmed and deduplicated). 422 invalid, 404 not the user's board, 409 if a column or card id belongs to another board. `save()` is shared with the AI chat.
- `ai.py`: OpenRouter via the `openai` SDK. `ask(messages, schema=None)`; with a Pydantic schema it requests strict Structured Outputs. Model `nvidia/nemotron-3.5-super-vl:free`; key from `OPENROUTER_API_KEY`.
- `chat.py`: `POST /api/boards/{id}/chat` with `{message, history}`. Sends the system prompt (today's date and the board as JSON), the history and the message; the model replies `{message, board | null}`. The AI board nests cards (all fields) inside columns and may add, remove, rename and reorder columns; `from_ai_board` maps it back and gives new or unknown column and card ids a fresh uuid. An invalid board is not saved (apology message); an AI failure is a 502. If the board changed while the model was working, nothing is saved and the user is asked to retry (`BOARD_CHANGED`). Returns `{message, board}`, where `board` is the saved board only if it changed.
- `check_ai.py`: manual connectivity check (`uv run --env-file ../.env python check_ai.py` asks "What is 2+2?").
- `auth.py`: `POST /api/register` (username 3 to 32 of letters, digits, `.`, `_`, `-`, trimmed, unique ignoring case; password 8 to 128 characters; 409 if taken; signs in), `POST /api/login` (401 "Invalid username or password"), `POST /api/logout`, `GET /api/me` (`{username}`), `PUT /api/me/password` (`{current, new}`; 403 if current is wrong; signs out other sessions), `DELETE /api/me` (`{password}`; deletes everything the user owns). The session is an HttpOnly, SameSite=lax `session` cookie. `current_user` is the dependency that protects routes and returns `{id, username}` (401 without a valid session). Known limits: the cookie is not `secure` and there is no login attempt limit; add both before exposing the app beyond localhost.

## Configuration

- `OPENROUTER_API_KEY`: from `.env` in the project root (Docker passes it with `--env-file`; locally use `uv run --env-file ../.env`).

- `DB_PATH`: database file. `/data/pmapp.db` in Docker (named volume `pmapp-data`, owned by the non-root `app` user), `backend/data/pmapp.db` locally (gitignored).

## Tests

`uv run pytest --cov` (fails below 100 percent coverage; live AI tests skipped). `uv run --env-file ../.env pytest` also runs the live tests in `test_ai.py` and `test_chat_live.py`, which call the real model and can be slow or flaky. `tests/conftest.py` points every test at a temp database in a folder that does not exist yet, and provides the `client`, signed-in `authed` (demo user), `board_id` (their first board) and `alice` (a second registered user with her own client) fixtures. `test_main.py` covers `/api/hello`; `test_db.py` covers creation, migrations (including rollback of a failing one), the demo seed and constraints; `test_auth.py` every account route; `test_boards.py` board CRUD, validation, per-user isolation and id reuse; `test_chat.py` scripts model replies (create, edit, move, columns, invalid boards, history, concurrent edits, failures).
