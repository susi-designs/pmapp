# Frontend overview

Next.js 16 (App Router, static export), React 19, TypeScript, Tailwind CSS 4, shadcn/ui (Radix base, `nova` preset, lucide icons), dnd-kit. Built to `out/` and served by FastAPI from `backend/static`.

## Structure

- `src/app/layout.tsx`: fonts (Inter as `--font-inter` for body, Manrope as `--font-manrope` for h1 to h3), `ThemeProvider` from next-themes (`class` attribute, system default), `TooltipProvider`, Sonner `Toaster`.
- `src/app/page.tsx`: renders `App`.
- `src/app/globals.css`: shadcn theme. Brand colours as hex tokens in `:root` (light) and `.dark`: `primary` purple (solid buttons), `ring` blue `#209dd7` (focus), `secondary`/`muted`/`accent` ice blue, `foreground` navy, plus a custom `highlight` gold token (`bg-highlight`, `text-highlight-foreground`) used for column tops and due-today and medium-priority chips. All text pairs meet 4.5:1, input borders and rings 3:1.
- `src/components/ui/`: generated shadcn components (alert-dialog, avatar, badge, button, calendar, card, dialog, dropdown-menu, input, label, popover, progress, select, separator, sheet, sonner, textarea, tooltip). Add more with `npx shadcn@latest add <name>`; edit only when needed. `cn` comes from shadcn's `cn` package (replaces clsx plus tailwind-merge), re-exported by `src/lib/utils.ts`.
- `src/components/ThemeToggle.tsx`: icon button "Toggle theme" with a tooltip; switches light and dark (next-themes stores the choice; the system preference is the default).
- `src/lib/api.ts`: `send(method, path, body?)` calls the backend with a JSON body and resolves to `null` when the server cannot be reached; `UNREACHABLE` is the shared message for that case.
- `src/lib/types.ts`: `Card { id, title, details, dueDate, priority, labels }`, `CardFields`, `Column { id, title, cardIds }`, `Board { cards: Record<id, Card>, columns }`, `BoardSummary { id, name }`.
- `src/lib/board.ts`: pure, immutable helpers: `findColumnId`, `moveCard`, `newCard`, `addCard`, `deleteCard`, `updateCard`, `renameColumn`, `addColumn`, `deleteColumn` (with its cards), `moveColumn`, `parseLabels` (comma separated, trimmed, deduplicated, at most 8 of 24 characters), date helpers `today` (local YYYY-MM-DD), `dueStatus`, `formatDate`, and `labelColor` (a stable tint per label from theme tokens).
- `src/components/App.tsx`: auth gate. `GET /api/me` decides (401 or no server means signed out); renders nothing until it answers, then `Login` or `Workspace` (keyed by username).
- `src/components/Login.tsx`: shadcn Card with one form that switches between "Sign in" (`POST /api/login`) and "Create account" (`POST /api/register`; the rules are shown as a hint). Visible labels "Username" and "Password". Errors inline: "Invalid username or password", 409 "That username is taken. Try another one.", 422 points to the rules, unreachable server. The submit button is disabled while the request runs. Toggle buttons: "Create an account" / "Sign in instead". Theme toggle at the top right.
- `src/components/AccountMenu.tsx`: DropdownMenu on an avatar button (accessible name "Account <username>"): "Signed in as", "Change password" (Dialog: current and new password, 403 and 422 messages, success toast "Password changed"), "Delete account" (destructive; AlertDialog asking for the password, success toast "Account deleted", then back to sign in), "Log out". The forms are separate components rendered inside the dialog content, so they reset each time they open.
- `src/components/AppShell.tsx`: the page frame, one viewport tall: a one-row header (app name, a `title` slot, an `actions` slot, theme toggle, `AccountMenu`) above `main`.
- `src/components/Workspace.tsx`: loads `GET /api/boards`, opens the board in the URL hash (`#board-<id>`, written with `history.replaceState`) or the first one, and creates, renames and deletes boards. Renders `Board` (keyed by board id) with `BoardSwitcher` as its title, or, for a user with no boards, an empty state ("You have no boards yet", board name field, "Create board"). Renders nothing until the first board has loaded, so the header is never replaced under the user. Failures show the toast "Something went wrong. Reload the page and try again."
- `src/components/BoardSwitcher.tsx`: the board name as the h1 (a button: click to rename in place with `InlineEdit`, label "Board name") and the "Boards" DropdownMenu: the boards (check mark and `aria-current` on the open one), "New board" (Dialog with `NameForm`), "Rename board" (starts renaming in `onCloseAutoFocus`, after the menu releases focus), "Delete board" (AlertDialog "Delete <name>?").
- `src/components/NameForm.tsx`: board name field (label "Board name", up to 60 characters) with a submit button and an optional extra button.
- `src/components/InlineEdit.tsx`: a focused, selected text field for renaming in place: Enter or blur saves (trimmed, only if changed and not blank), Escape cancels (a ref stops the blur during unmount from saving).
- `src/components/Board.tsx`: owns one board's state and the dnd-kit `DndContext` (pointer and keyboard sensors, `closestCorners`, drag overlay, screen reader announcements with card and column names). Renders `AppShell` with "N of M done" (cards in the last column), a Progress bar and `ChatSheet` in the header, then the columns, which share the width (at least 224px from `sm`, 85vw on phones; the row scrolls sideways with snap points and matching scroll padding) and an "Add column" button (the new column opens its title for editing). Columns and cards are sortable in one context; `data.type` ("column" or "card") tells drags apart. Cards move across columns during drag-over; a column moves on drop. Every change is saved with `PUT /api/boards/{id}`: optimistic, queued so saves arrive in order; a failure shows the toast "Could not save your changes. Reload the page to see the saved board." (deduplicated). Card drags save once, on drop or cancel; column drags only when the order changed.
- `src/components/Column.tsx`: sortable column (grip "Drag column <title>") that is also the drop target for cards: a section (`data-testid="column"`, `aria-label` the title) with a gold top border, click-to-rename title (label "Column title"), count Badge, "Delete column <title>" (shown on header hover or focus, always on touch; AlertDialog "Delete <title>?" when it has cards; hidden for the last column), a scrolling card list with a dashed "Drop cards here" zone when empty, and `AddCard`.
- `src/components/CardItem.tsx`: `CardView` (look; also the drag overlay) and `SortableCard` (`data-testid="card"`). The grip "Drag <title>" is the only drag activator (no nested buttons). Edit and Delete ("Edit <title>", "Delete <title>") sit in a small tray at the top right, shown on hover or focus and always on touch screens (the text gets right padding there). Badge chips: priority (screen reader text "Priority:"), due date ("Overdue <date>" in red, "Due today" in gold, otherwise "Due <date>"; text, not only colour), labels.
- `src/components/CardDialog.tsx`: Dialog "Edit card": Title, Details, Due date (Popover with Calendar; button named "Due date: <date or No due date>"; "Clear due date"), Priority (Select: None, Low, Medium, High), Labels (comma separated). "Save card" needs a title.
- `src/components/Chat.tsx`: `useChat(boardId, onBoard)` holds the conversation; `Board` owns it, so it survives closing the panel and resets when the board changes (Board is keyed by id). The user message shows at once and stays if the request fails; history is sent with each `POST /api/boards/{id}/chat`; a reply with a board replaces Board's state without a PUT (the backend saved it). `ChatSheet`: "Ask AI" (icon only below `sm`, the text stays for screen readers) opens a non-modal shadcn Sheet "AI assistant" on the right: no overlay, outside clicks do not close it, so the board stays usable and visibly updates. Focus moves into the message box (label "Chat message") on open and back to Ask AI on close (Escape or "Close"). Suggestions on an empty chat fill the box; "Thinking..." while waiting; error "The AI request failed. Send your message again to retry."; Enter sends, Shift+Enter adds a line; messages have `data-testid` `chat-user` / `chat-assistant`.
- `src/components/AddCard.tsx`: "Add card" opens a title field (label "Card title"); Enter adds and keeps it open for the next card, Escape or Cancel closes.

## Styling notes

- shadcn components style variants with data-attribute selectors (for example `data-vertical:self-stretch`), which beat a plain utility of the same property. Override with the same variant (`data-vertical:self-center`).

## Config and tests

- `next.config.ts`: production builds use `output: "export"`; `next dev` instead rewrites `/api/*` to `API_URL` (default http://localhost:8002, a local uvicorn), because export mode does not allow rewrites. `reactCompiler`, Tailwind via the turbopack loader. No `cacheComponents` or `partialPrefetching`: they enable PPR, which export mode rejects.
- Unit tests: Vitest (jsdom, Testing Library), `src/**/*.test.tsx`: `App.test.tsx` (sign in, sign up, errors, log out, change password, delete account), `src/lib/board.test.ts` (helpers). Helpers in `src/test/`: `renderWithProviders` (the layout providers plus the Toaster), `demoBoard()` (3 columns, 3 cards) and `fakeServer()` (a fake backend for the account, board and chat routes installed as `fetch`; `signedIn`, `boards`, `down`, `failSaves` and `chat` (the reply, or a promise of it, or "fail") control it; `puts` counts saves and `chats` records chat requests). `vitest.setup.ts` stubs `matchMedia` (next-themes) and `ResizeObserver`, pointer capture and `scrollIntoView` (Radix). `Board.test.tsx` covers board, column and card flows and the board menu (only `Date` is faked, at March 10, 2026); `Board.drag.test.tsx` mocks `DndContext` to capture its handlers and calls them with drag events (jsdom cannot drag; Playwright drags for real; the overlay only renders during a real drag); `Chat.test.tsx` (send, pending, history, board update, failure, close and reopen, board switch); `ThemeToggle.test.tsx`. Coverage threshold 80 percent, excluding `src/app/` (wiring), `src/components/ui/` (generated) and `src/test/`. No `@vitejs/plugin-react`: Vite compiles TSX itself.
- E2E: Playwright in `e2e/`, against the running container (http://localhost:8001, `BASE_URL` overrides), one worker. `auth.spec.ts` (sign in and out, sessions, HttpOnly cookie), `accounts.spec.ts` (sign up with a unique name per run because the database persists, taken names, change password, delete account, keyboard use of the menu and dialogs), `board.spec.ts` (cards, columns, mouse and keyboard drags, persistence across reload), `boards.spec.ts` (create, switch, URL hash, rename, delete, empty state), `chat.spec.ts` (AI mocked at the network layer: reply and board update, pending state, error, focus and closing, board usable while open, phone width), `shell.spec.ts` (shell and theme). `e2e/helpers.ts`: `signIn` and `register` wait for the API response (scrypt is slow on purpose, so reloading straight after clicking would race the cookie), `openAccount`, `logOut`, `resetBoard` (restores the demo user's single demo board through the API and signs the page's browser in as them), `column`, `drag` (mouse), `saved` (waits for the PUT an action triggers). The database persists between runs, so tests never rely on state another test leaves.
- Test hooks: `data-testid="column"` and `"card"`; accessible names "Account <username>", "Toggle theme", "Boards", "Board name", "Column title", "Card title", "Drag <title>", "Edit <title>", "Delete <title>", "Drag column <title>", "Delete column <title>", "Ask AI", "Chat message", "Close", labels "Username", "Password", "Current password", "New password", "Enter your password to confirm". Next.js adds an empty `role="alert"` route announcer, so tests find errors by text.
